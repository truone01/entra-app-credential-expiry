Rotate an Entra ID app registration client secret without downtime

An app registration can hold several secrets and certificates at once. That is what makes rotation without downtime possible. Use this order:

  1. Add a new credential. App registrations > your app > Certificates & secrets > New client secret (or upload a certificate). Copy the value now; it is shown only once. Don't delete the old one.
  2. Update every consumer. Key Vault secrets, app settings, connector configurations, CI/CD variables. The app's owners usually know where it is used. The expiry report with -IncludeOwners lists them.
  3. Confirm. In Sign-in logs > Service principal sign-ins, filter by the app and check the credential key id. Wait until only the new key id appears.
  4. Delete the old credential.

Make the next one less painful

  • Prefer certificates or managed identities / workload identity federation over secrets where you can.
  • Use the shortest lifetime you can rotate reliably. Microsoft caps secrets at 24 months.
  • Set a reminder 30 days ahead, or run a scheduled expiry check.
